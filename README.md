## 整理原则

- 25 个 ROS 包按功能分目录；原始源码、launch、参数、模型与资源内容没有修改。
- 998 个原始文件均在本地副本保留；逐文件 SHA-256 已与 ZIP 内容比较通过。
- 仅一份包含疑似访问密钥的配置不上传：`源码/大模型服务与应用/大模型基础服务/large_models/config.py`。使用前从本地保留副本恢复，或自行提供等效私有配置；不要提交密钥。
- 大模型、网格、推理引擎等二进制资源通过 Git LFS 保存；保留原有重复资源，避免改动程序资源定位。
- 原工作空间根文件放在 `原始环境资料/`，包含保留原内容的子模块配置、忽略规则、环境脚本与命令资料，供追溯，不自动应用。

## 中文目录导航

实际仓库目录已改为中文；各 ROS 包名称、Python 模块名与源码文件内容保持原样。

- **源码/**：按功能归类的 25 个 ROS 包，外层包目录也使用中文名称。
- **文档/**：分析报告、原始文件校验清单和审计资料。
- **原始环境资料/**：厂商原始环境脚本、命令与工作空间配置。

内部 Python 模块目录和包内 `launch`、`config` 等资源目录保留原名，以保持源码内容和包内结构。分析报告记录的是最初整理方案，当前实际路径以本页及文件清单为准。

## 获取资源与构建状态

克隆后先安装 Git LFS，然后在仓库根目录运行：

```bash
git lfs install
git lfs pull
```

原环境脚本指向 ROS 2 Humble 和 Orin 的多个第三方工作空间。该副本完成了静态归类和内容一致性检查，**尚未在 Linux/Orin 上构建或运行验证**。

源码仍含 `/home/ubuntu/ros2_ws/src/...` 等旧绝对路径，目录归类后这些路径不会自动更新。原 `.typerc` 的 `need_compile=False` 分支尤其依赖旧布局。也存在未安装的嵌套资源、未声明的依赖和缺失入口等待核查项目，因此当前整理不能被当作开箱即用安装包。详见分析文档；本次按要求不修复源码。

`calibration` 引用 `test_stand`，`openclaw_controller` 引用大模型示例，不能把这些目录直接视为相互独立的可选组件。

## 来源与许可

来源为用户本地厂商资料 `src_ros2-main.zip`；没有导入原 Git 历史。保留各包原有作者、许可证声明和 LICENSE 文件。多数包许可证仍为 TODO，未授予统一新许可证；第三方 SDK、模型和网格的再分发许可待确认。公开可见不代表对第三方材料授予新的使用或再分发许可。

原 `.gitmodules` 指向内网服务，作为历史资料保留在 `原始环境资料`，当前大模型源码以普通目录纳入本仓库。
